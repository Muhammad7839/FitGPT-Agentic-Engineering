# Calibration Fault Plan: Tester Output-Schema Mismatch

## Selected failure mode

Tester output-schema mismatch. The required `## Result` heading will be changed to `## Status` in the actual project-scoped Tester definition.

The preferred incomplete-handoff fault was not selected because this repository has handoff guidance and templates but no deterministic runtime handoff builder. Altering a documentation-only template would not reliably change the handoff generated by a model. The Tester definition is consumed directly by Claude Code, so a one-line output-contract fault is both realistic and repeatable.

## Development task

`COURSE-FITGPT-001`, the existing backend onboarding documentation workflow. This is the established development task used by the current evaluation baseline; it is not one of the locked `HO-01` through `HO-07` tasks.

## Expected correct behavior

- Tester receives the approved focused target `backend/tests/test_config_startup.py` and the mandatory prerequisite evidence.
- Tester invokes the bounded dummy `mcp__coursetools__test_runner` once when the handoff is complete.
- Tester returns the exact structured heading `## Result` with one of `Pass`, `Fail`, or `Blocked`.
- The evaluator accepts a Tester `Pass` only when the required heading and one matching actual dummy tool event are present.
- No result is represented as real pytest or complete backend, deployment, integration, or production health.

## Exact component to alter

`.claude/agents/tester.md`, which owns the Tester's required output contract.

## Exact induced fault

Change only the required heading:

```diff
-## Result
+## Status
```

No other agent instruction, handoff requirement, tool grant, application file, test, MCP source, or evaluation threshold will change in the induced-fault commit.

## Expected evidence

- A fresh Claude Code Tester conversation using the faulted project-scoped definition.
- The exact Tester handoff and output.
- Stream JSON showing any `file_read` and `test_runner` events.
- A normalized transcript whose Tester output contains `## Status` rather than `## Result`.
- Repository manifests proving that the run did not change application code, tests, MCP files, memory, or the locked holdout.

## Expected failing check

A focused permanent deterministic check named `tester_output_schema` will require the exact ordered Tester headings and an allowed result under `## Result`. It is expected to fail the preserved before-fix transcript because `## Result` is absent.

The current broader controlled-test check may also reject the normalized Tester verdict. The focused check is still needed because it identifies the output-contract defect directly instead of reporting only a downstream missing-Pass symptom.

## Ownership and proposed fix layer

Prompt layer. The defect is introduced in the Tester's own required output format, and the narrow fix is to restore `## Result` in that same definition.

Changing routing would not repair the malformed output contract. Broadening tools would add unrelated risk. Relaxing the normalizer or evaluator to accept `## Status` would weaken the committed contract instead of correcting the producing prompt.

## Stop conditions

- Any changed path beyond this plan during planning, or beyond `.claude/agents/tester.md` during fault induction.
- Any modification to `docs/holdout-task-set.md` or checksum mismatch from `e3aa9cdcec7b643507b7dd6f03ea15d92cfb6ed5fcacc4f56f5b2a8631631f32`.
- Any application-code, production-test, MCP-source, persistent-memory, credential, or real-environment change.
- Any real external issue-tracker call, Git remote contact, push, or history rewrite.
- Any attempt to tune against a locked holdout task before the clean holdout measurement.
